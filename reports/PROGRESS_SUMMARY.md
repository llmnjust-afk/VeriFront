## 一、研究思路

### 1.1 研究问题

科研 Agent（如 CodeAct 型工具调用智能体）在多步科研任务中的成败，究竟在哪些步骤上**真正依赖前沿模型能力**？这种依赖能否被一个客观、可复现的指标——**步骤级可验证性（objective step-level verifiability）**——所预测？

当前对"前沿能力需求"的讨论大多停留在模型层面的整体基准对比。我们的核心主张是：**依赖是步×模型特异的（step×model specific）**——同一条执行轨迹中，某一步换成小模型会摧毁整条 run，另一步换成小模型毫无影响，且"哪一步失效"随替换模型不同而系统性地不同。若成立，则"是否需要前沿模型"不是 run 级的二值判断，而是可以定位到步、并按可验证性结构预测的。

### 1.2 方法：步级反事实替换（P1-CF）

以冻结配置的前沿模型 run（parent）为基底，构造反事实：

1. **重放** parent 的第 1..t−1 步（消耗 0 步预算，remaining = 12 − (t−1)）；
2. **保真验收**：逐步比对观察（observation diff），要求 ≥90% 步观察一致（P1 实测全部一致，diff 仅为 matplotlib 临时缓存路径等环境噪声）；
3. **接管**：在第 t 步换入替换模型（edit model）重新生成动作并继续执行至终；
4. **评测**：与 parent 相同的客观判分（Y ∈ {0,1}）。

三臂设计分离两种解释：

| 臂 | 含义 | 回答的问题 |
|---|---|---|
| `frontier_resample` | 同一前沿模型温度 0 重采样 | 单纯非确定性的噪声底线 |
| `local_replace`（mini / deepseek / qwen） | 换入更弱/不同类模型 | 步骤是否依赖"前沿级"能力 |

对照点是人工标注为**可验证性强（neutral）**的步：若三臂在 neutral 点都不降低成功率，说明标注效度良好、管线本身不引入系统性破坏。

### 1.3 与可验证性框架的联结

每个被试步按人工标注分为：

- **critical**：标注为"依赖前沿能力"（不可客观验证 / 开放式生成）的步；
- **neutral**：标注为"可客观验证"（有明确判定标准）的步。

主假设 **H1a**：critical 步的替换会显著降低成功率（ΔSR < 0），neutral 步不会。
主假设 **H1b**：critical 步失效后，仅由前沿模型可修复（frontier-only repair）。

## 二、已完成的验证实验

### 2.1 基线实验（P1 frontier）

- 冻结配置：`gpt-5.5-2026-04-23`，12 步上限，温度 0，max_tokens 8192，沙箱降权执行（nobody，/tmp 隔离工作区）。
- 对 10 个科研任务实例（sab_5/18/35/37/40/44/58/60/85/92）执行 frontier run，产出 parent 轨迹与客观判分 Y。
- 判分采用客观指标（如表格任务的 Mean F1 阈值判定），全程不向 agent 暴露金标。

### 2.2 步级可验证性人工标注

- 对 parent 轨迹逐步标注（B 侧人类标注者），产出 `annotation_sample.jsonl`；
- 与任务金标 join 后得到候选实验点：**38 个点实例**（16 critical + 11 neutral + 11 neutral/failure 变体），全部满足重放就绪条件；
- 同一 (task, step) 可来自不同 parent run——聚合与分析一律使用 **(task, step, parent_stamp) 三元组键**（发现过键设计缺陷并修复）。

### 2.3 H1a：三臂反事实替换（全量扩展）

- 38 点实例 × 3 臂 × 2 重复，分 4 批执行（批 1–4），后续按分歧驱动原则复核补齐；
- **累计 397 条 run**（含试点 14 条、全量扩展、信号点复核）；
- 每条 run 附带完整元数据：`edit_step_parsed_action`（失效分层）、`replay_fidelity`（保真）、token 用量与耗时。

### 2.4 信号点复核与补齐

- 对 |ΔSR| ≥ 0.33 的信号点，将全部臂补至 n ≥ 4（部分点 n=6–8）；
- 发现并修复三类执行器缺陷：续跑器未 source 环境（401）、`result_exists` 只查存在性导致 rep2 被跳过（`--min-per-arm` 按数量补齐修复）、聚合器键不含 parent_stamp。

### 2.5 跨模型类复验（Qwen3-8B 本地推理）

- **动机**：mini 与 deepseek 均属前沿系 API 模型家族，需验证失效模式是否跨模型类保持；
- **设置**：Qwen/Qwen3-8B 经 vLLM 部署于本地 RTX 4090（32K 上下文，`enable_thinking: false` 关闭思维链，温度 0，输出上限 4096 tokens）；
- 对 6 个信号点的 7 个点实例执行与 2.3 完全相同的重放-接管-评测管线，每实例 4–8 条，**共 52 条 run，0 protocol 失效**；
- t40s2@305791 的三个 API 臂按分歧驱动原则补齐至 n=4（追加 6 条）。

### 2.6 失效机理分层分析

- 对每条替换 run 记录接管步的解析动作类型（`code` / `none` / `final`），区分**能力失效**（写了代码但跑错）与**协议失效**（根本没产出动作）；
- 对替换后 run 的执行轨迹做失败模式归类与自愈统计。

## 三、通过实验得到的结论

### 3.1 主结果：步×模型交互（H1a 成立，且强于预期）

**臂级汇总（critical 点成功率）**：resample 0.60 / mini 0.49 / deepseek 0.55——类别层面依赖弱；**neutral 点三臂一致**（0.61 / 0.66 / 0.62），标注效度良好。

**信号点（|ΔSR| ≥ 0.33，n=4–7 确认）四臂终版**：

| 信号点 | 类 | resample | gpt-5.4-mini | deepseek-v3.2 | Qwen3-8B | qwen ΔSR |
|---|---|---|---|---|---|---|
| t60 s6 | crit/succ | .71 | **.00** | .71 | **.25** | −.46 |
| t85 s2 | crit/succ | .83 | 1.00 | **.17** | .50 | −.33 |
| t40 s4 | crit/fail | 1.00 | .50 | .60 | **1.00** | .00 |
| t92 s1 | crit/succ | .75 | .75 | **.25** | **.00** | −.75 |
| t60 s4 | crit/succ | .71 | .33 | 1.00 | .50 | −.21 |
| t40 s2（双实例合并） | neut | .90 | .90 | .73 | .44 | −.44 |

**头条发现**：mini 的失效点集 {t60s6, t60s4, t40s4} 与 deepseek 的失效点集 {t85s2, t92s1, t40s2} **完全不重叠**。不存在"某一步对所有小模型都难"的简单规律——每一步撞上的是不同的模型。

### 3.2 跨模型类稳健性（Qwen3-8B 复验）

1. **合并效应显著**：Qwen3-8B 在 6 信号点上 20/44 (.45) vs 同点 resample 基线 26/35 (.74)，Fisher 精确检验 **p ≈ .008**——前沿模型定义的信号步对 7–8B 开源模型同样是真实失效面，不是 API 模型伪影；
2. **失效集"部分包含"**：Qwen 失效点覆盖 mini 的 t60s6（−.46）与 deepseek 的 t92s1（−.75，单点最强，p = .028）与 t40s2（合并 .44 vs .90）；
3. **失效面非单调收缩**：t40s4 上 mini 失效（.50）而 7B 的 Qwen **4/4 全过**。失效不是随模型规模单调放大，而是步的"可验证性形态"与模型先验的匹配问题；
4. 每个信号步的失效模型组合互不相同（t60s6: mini+qwen；t92s1: ds+qwen；t85s2: ds 主导；t40s4: mini-only）——**"每步撞上不同的墙"**，为论文 §5 的步×模型交互叙事提供最直接支撑。

### 3.3 修复实验（H1b：前沿-only 修复，带反例）

- 10 个 critical 点中 **8 个不可修复**（任何替换模型接管失效步后无法挽回）；
- 2 个 frontier-only 修复（t44 s4、t5 s2：只有重采样前沿模型能恢复）；
- **1 个反例**：t35 s1 被 deepseek-v3.2 修复（4/4）——说明"前沿依赖"在该步可被非前沿模型满足，标注需结合失效证据修正。

### 3.4 失效机理分层

- **能力失效 ≈ 90%**：接管模型写出了代码但执行结果错误（code 动作，eval 失败）；
- **协议失效 ≈ 10%**：接管步直接输出最终答案（跳过剩余步骤）或不产出动作；
- 输出格式错误的 run 中约 47% 在后续步自愈——协议失效多数可被轨迹动力学吸收，能力失效几乎不可逆。

### 3.5 方法论警示

- **温度 0 ≠ 确定**：relay 端重采样存在真实方差（t60 s2 neutral 点 resample 曾 0/4；t40s2@305791 补跑后 resample 自身 3/4）——所有臂级对比必须以"相对同点 resample 基线"的 ΔSR 报告，而非绝对成功率。

## 四、效度与限制

| 维度 | 状态 |
|---|---|
| 重放保真 | 全部 ≥90% 阈值；diff 仅环境噪声（临时缓存路径） |
| 标注效度 | neutral 点三臂一致（.61/.66/.62），无系统性破坏 |
| 统计功效 | 每臂 n=4–8，单点检验功效有限；信号以多实例合并 + 双实例互证缓解 |
| 任务域 | 单一科研任务套件（10 实例）；外推到其他域待 P2 |
| 前沿模型 | 单一（gpt-5.5-2026-04-23）；未测前沿系内变异 |
| Qwen 输出上限 | 32K 上下文下 max_tokens cap 4096，对极长轨迹的生成余量有约束 |
