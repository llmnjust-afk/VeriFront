## A6 接管后模型控制策略（因果定义）

**原报告口径**：未明确声明第 t 步之后由谁生成。

**原始证据**（代码审计）：`scripts/run_cf_point.py` 中
```python
def client_for_step(step_i):
    if step_i == args.at_step and edit_client is not None:
        return edit_client
    return frontier_client
```
`verifront/agents/codeact.py:301` 每步调用 `client_for_step(step_i)`；`is_cf_edit_step` 标记与之一致。

**核查结论**：
- **P1 协议 = 单步替换**：仅第 t 步由替换模型生成，第 t+1 步起恢复前沿模型（gpt-5.5）。plan §1.2 A6 担心的"单步动作 × 后缀模型能力"混杂**不存在**。
- 因果表述应写为："第 t 步动作差异 →（由同一个前沿模型执行的）后续轨迹动力学 → 终局 Y"。
- plan §5.2 的对照实验相应调整：P1 数据已覆盖"单步替换"侧；**需新增"后缀接管"臂**（第 t 步起持续使用替换模型，需为 `run_cf_point.py` 增加 `--suffix-takeover` 开关，实现为 `client_for_step` 恒返回 edit_client）以回答"真实部署整条 run 用小模型时，步骤敏感性如何放大"。
