# P2b 反馈干预实验设计（plan §5.5 试点）

**状态**：设计冻结稿（代码实现待全步扫描完成后）

## 1. 研究问题

在客观验证器可得的接管步上，**增强的客观验证反馈**能否缩小替换模型与前沿重采样之间的成功率差距（DiD）？即：失效是"能力缺失（反馈也救不了）"还是"反馈缺失（信息到位即可修复）"。

## 2. 2×2 设计

| | 原始反馈（P1 协议） | 增强客观反馈 |
|---|---|---|
| frontier 重采样 | 单元格 A（复用 P1 数据） | 单元格 B |
| 替换模型（mini 或 qwen） | 单元格 C（复用 P1 数据） | 单元格 D |

- **操纵**：接管步的代码执行结束后，若触发重试窗口（见 §3），反馈内容不同：
  - 原始反馈：stderr/观察原文（P1 现状）；
  - 增强反馈：stderr + **结构化校验器报告**（显式列出预期产物、缺失项、数值 sanity 结果）。
- **公平性约束**：两臂的额外预算/重试机会数完全相同；增强反馈只重述"执行当时可合法获得的信息"，**绝不包含金标、金标统计量或最终答案**。

## 3. 重试窗口机制（统一，两臂同构）

接管步执行后：
1. 若 `exit_code != 0` 或产物校验失败 → 进入**一次反馈重试**：同一接管模型在同一消息历史上追加一条验证反馈消息，重新生成第 t 步动作并继续；
2. 对照单元（A/C）走**相同机制**但反馈消息只含"上一步执行失败，请检查并修正"（无 stderr 细节、无校验报告）；
3. 重试后无论成败都不再有第二次重试（预算规则与 P1 一致：remaining = 12−(t−1) 不变，重试不额外消耗步号）。

## 4. 校验器构造（任务级、不泄金标）

试点对象：t40（grid_search ML 任务）与 t60（数据分析任务）的信号步及全步扫描中失败率最高的 2–3 步。

| 校验项 | 内容 | 泄金标风险 |
|---|---|---|
| 产物存在性 | `pred_results/` 预期文件在 | 无 |
| schema 校验 | 列名/行数/非空/dtype | 无 |
| 数值 sanity | 无 NaN、预测分布合理、类别集合 ⊆ 训练标签集 | 无（标签集来自输入数据，非金标） |
| 运行时不变量 | 中间产物行数 == 输入行数（t60 类 join/统计任务） | 无 |

校验器脚本作为**独立文件**进 repo（`verifront/eval/validators_sab{40,60}.py`），输出统一 JSON 报告；agent 的 prompt 中只注入报告文本。

## 5. 预算与样本

- 试点规模：2 任务 × 3 步 × 2 条件（B/D 各 4 条）≈ 48 run；A/C 单元复用 P1/扫描数据（同点同臂），必要时补 4 条/格对齐预算；
- 预估成本：~35 CA（frontier 续跑部分）；
- 分析：混合效应模型（条件 × 模型交互），主检验 = (D−C) 与 (B−A) 的交互方向：若 (D−C) > (B−A)，说明增强反馈对替换模型的增益大于对前沿的增益 → 支持"反馈缺失"成分；若交互 ≈ 0，支持"能力缺失"成分。

## 6. 实现清单
