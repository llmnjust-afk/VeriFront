# P2 §4.2 二次标注澄清说明（第二轮，κ<0.6 维度）

**适用**：标注者 A 与 B 各自独立执行 ｜ **范围**：仅 F1、F3、F4、F5、F6 五维（F2 κ=0.83、F7 一致率 1.00，两维**不重标**）｜ **依据**：Codebook v1.3 冻结定义
**流程**：双方读本说明后独立重标 → 交回 → 重算 κ → 仍 <0.6 的维度进入仲裁（≤1 级取均值 / >1 级共识）

**核心提醒**：七维是**七个不同的问题**。同一段观察输出，在 F1 下可能毫无证据价值，在 F3 下却可能是关键证据。判定前先问该维的"焦点问题"，再看观察/代码里有没有回答它的证据。**"输出信息丰富、可复查"本身不是任何一维的判据。**

---

## F1 objective_verifiability — 焦点问题：「这一步的工作产出，其**对错**有没有客观判定标准？」

- 判定对象是**该步产出的正确性**，不是"观察文本是否可以核对"。打印出来的版本号、行数、文件结构**没有对错可言**（打印什么就是什么，没有预期答案可比）——这类步骤的产出不存在"做对/做错"，→ **0**。
- 产出的正确性可量化、但"做对了"还依赖口径或后续解释（如统计口径、阈值选择、特征选择）→ **1**。
- 产出的正确性可由脚本直接判定（任务指令给定公式可独立重算、schema 明确匹配）→ **2**。
- **常见误判**：把"我能看懂输出/输出很详细"当作对错可判定。可读性 ≠ 可验证性。

## F3 feedback_availability — 焦点问题：「agent 执行这步时，拿到的反馈里有没有**对错信号**？」

- F3 衡量的是**验证反馈**（能告诉你"做对了还是做错了"的信号），不是**信息性输出**（能告诉你"世界长什么样"的输出）。
- 打印库版本、函数签名、源码、数据结构 = 信息性输出，**不构成对错反馈**；这类执行的对错信号只有退出码/异常栈级别的通用信号 → **1**。
- 打印了**任务专用**的对错信号（CV 指标、断言结果、与参考值的对比、逐项计数检查结果）→ **2**。
- 执行中断且无任何输出（如超时、崩溃）→ 只有"未完成"这一个通用信号 → **1**（有信号但仅此而已）。
- **常见误判**：把"输出很丰富"升级为 2。丰富 ≠ 有对错信号。

## F4 feedback_informativeness — 焦点问题：「**假设这一步做错了**，观察能把错误定位到多细？」

- 前提是先有反馈（F3=0 时 F4=0）。F4 衡量**错误定位粒度**，不是"数值是否可复查"。
- 只有通过/失败（或超时）信号，不知道错在哪 → **0**。
- 能定位到模块/函数/变量级（异常栈指向某个函数、缺失清单指向某几个键、某项指标异常）→ **1**。
- 定位到具体行/具体值，可直接指导修复（具体数值异常如 0 峰/NaN、集合比对给出差异项、断言失败的具体表达式）→ **2**。
- **常见误判**：把"输出里有具体数字"当 2。数字再多，如果做错时它们无法指示错在哪，仍是 1。

## F5 state_dependence — 焦点问题：「这一步的正确执行，**依赖多少前面步骤留下的东西**？」

- 证据来源是**代码对前序产物的引用**：读哪个文件（该文件是前序步写的还是任务数据包自带的？）、用了哪些前序得出的变量/结论、是否沿用了前序建立的隐式约定（命名、编码规则、顺序）。
- 自包含（只读任务自带数据/只打印）→ **0**；依赖 1–2 个前序产物且名实对应 → **1**；依赖跨多步累积的隐式约定 → **2**。
- **常见误判**：用"打印了什么"回答 F5。F5 与观察丰富度**完全无关**，只看代码的输入从哪来。判断时逐个问：这个文件/变量/约定是谁产生的？在任务材料里吗，还是在前面步骤里？

## F6 recoverability — 焦点问题：「**假设这一步做错了**，错误会在后面被发现并修复吗？」

- **0 难**：错误产物污染下游（后续步直接消费这个结果、无校验点），或错误认知静默进入后续上下文且无检查能发现；
- **1 可重试**：重新执行这一步本身就能覆盖错误（如重新计算、重新写文件）；
- **2 可局部修补**：有明确校验点能**检测**到错误，且能**局部**修补而不牵连其他产物。
- **常见误判**："可以重新运行" = 1（重试），不是 2。给 2 必须回答：下游**有什么校验点**会检测到这个错误？没有具体校验点就不能给 2。另外注意 F6 只关于"后续能否发现修复"，不关于"错误有多严重"。
